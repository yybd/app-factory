# 3 — זרימת הסטודיו, כפי שהיא באמת רצה

**רשומה, לא הוראות.** זהו רצף ההשקה המלא של סטודיו אחד, שנכתב תוך כדי הרצתו: כל סקיל
לפי סדר, ממה כל אחד שואב, והכללים שנלמדו מכך שטעו בהם. הוא מניח את הצורה של אותו
סטודיו — ריפו **האב** משותף לפרופילים ולטקסט החנות, ריפו **אתר** נפרד, וכמה אפליקציות
— ומזכיר שלושה סקילים שלא נשלחים במרקטפלייס הזה (`add-app-to-site`, `reference-page`,
עבודת הקמפיינים), כי הם חיים בריפו האתר שאליו הם שייכים.

**מה לקרוא במקום**, אם אתם משלחים אפליקציה: [`APP-LIFECYCLE.he.md`](../../APP-LIFECYCLE.he.md)
בשורש, שהוא אותו רצף כשהאב אופציונלי ורק עם הסקילים שנשלחים כאן. הקובץ הזה הוא מה
שההוא זוקק ממנו, והוא נשמר כי החלופה שנפסלה היא בדרך כלל החלק היקר לגלות מחדש.

**מתוארך.** הוא מתאר את המצב בזמן הכתיבה; היכן שהוא סותר את הקוד של היום — הקוד צודק.

---

## זרימת חיי אפליקציה — הסטודיו

מפה אחת מ-source ועד "חי בכל מקום": הבינארי, החנויות (App Store + Google Play),
האתר (<your-site>) והשיווק. **מקור האמת לכל קופי הוא `<slug>/profile.md` שב-Hub** —
שום טקסט לא נכתב לפני שהפרופיל קיים, ושום סקיל לא ממציא; הכול נגזר מהפרופיל.
מעליו, ה-`README.md` של הריפו (בניהול `app-identity`) הוא מקור-האמת ל**זהות** (שם + רשימת פיצ'רים + Pro),
וה-`app-profile` שואב ממנו. ה**מטא-דאטה הרב-לשונית** של החנויות חיה ב-Hub תחת `<slug>/store/` (ה-SoT שלה),
ומסונכרנת ל-`fastlane/` של הריפו **רק בזמן ה-deliver** (עם ולידציה שחוסמת העלאה אם חסר נתון).

המכניקה גלובלית · התוכן ב‑Hub · האתר ב‑repo של האתר.

## א. איפה כל סקיל חי — ומה התגיות אומרות

*נכתב מחדש 2026-09-09. הנוסח הקודם כאן היה שגוי בכל פרט*: הוא תיאר שלושה סקילים
ב‑Hub (יש **אפס** — נמחקו), סקיל אחד ב‑repo של האתר (יש **שלושה**), ו‑22 סקילים
ב‑`~/.claude/skills/` — נתיב שאינו נטען יותר, ו‑repo ששמו שונה. **אל תגזרו מכאן מיקום.**

**שום דבר אינו גלובלי.** הסקילים חיים ב‑`$APP_FACTORY/plugins/`, מותקנים
כמרקטפלייס, וכל מסלול מופעל **לפי ריפו** — ב‑`.claude/settings.json` של אותו ריפו,
שנכתב על ידי `factory/enable.py` או על ידי הרישום של grove. ריפו שלא הפעיל כלום לא
טוען כלום. היוצאים מן הכלל הם הסקילים של ריפו האתר עצמו, הכבולים לעץ שלו ולא עוזבים
אותו לעולם.

מי קובע מה יושב איפה, ולמה — [`1-shared-context-repos.he.md`](1-shared-context-repos.he.md):
המבחן הוא **על כמה עצים פעולה אחת משתרעת**, לא באיזה repo היא נוגעת.

### התגיות בהמשך אינן "איפה הסקיל נטען"

הן נשארו כי הן עדיין נכונות — אחרי ששינו משמעות. הן אומרות **איפה הסשן חייב
לעמוד**, וזה לא אותו דבר:

| | הסשן עומד ב… | ולמה דווקא שם |
|---|---|---|
| `[G]` | **ריפו האפליקציה** | ה‑build, הסימולטור, הבינארי, וה‑git שהקומיט נוחת בו — אף אחד מהם לא זז |
| `[H]` | לא נדרש מקום מסוים | ה‑Hub הוא **נתונים**, נכתב בנתיב מכל מקום. הסקילים שכותבים אליו גלובליים |
| `[B]` | **ריפו האתר** | סקילי האתר נטענים רק שם |

**`[H]` הוא היחיד שהתרוקן ממשמעות של מיקום** — לפני ההגירה הוא אמר "פתח סשן
ב‑Hub", והיום הוא אומר רק "התוצר נוחת ב‑Hub".

## ב. תרשים הזרימה: מ-0 עד "חי"

```
0a app-identity          ריפו [G]       ← README: שם + פיצ'רים + Pro (מקור-אמת לזהות)
│
0b app-profile           Hub [H]        ← profile.md (שואב מה-README). אין עדיין מדיה.
│
├─ 1  בינארי             ריפו [G]   ┐  מתקדמים במקביל
├─ 2  דף פרטיות          `<site>` [B] ┘  = add-app-to-site · Phase A (בלי מדיה)
│
3  מדיה → Hub            ריפו [G]       ← נקודת המדיה (צריך build מ-1)
│
4  קופי → Hub/store      Hub [H]        ← כותב מטא-דאטה ל-Hub (ה-SoT). צריך profile + מדיה
│
5  שליחה (deliver)      ריפו [G]       ← ship מפעיל app-store-deliver: sync (מאמת! חוסם) → ASC API. צריך store מ-4, ו-2 לפני-כן
│
6  נוכחות באתר           `<site>` [B]   = add-app-to-site · Phase B (tier 2/3 צריכים מדיה)
│
7  שיווק + מעקב          Hub [H] / גלובלי [G]
```

> **`add-app-to-site` מתפצל סביב המדיה (שלב 3):** Phase A (שלב 2 — דף פרטיות) רץ **לפני** המדיה
> ו**לא תלוי בה כלל**; Phase B (שלב 6 — נכס באתר) רץ **אחרי** המדיה, ו-tier 2/3 **דורשים** את `media/apple/`.
> בלי מדיה אפשר כבר עכשיו: דף פרטיות (Phase A) או כרטיס tier 1 (אייקון + משפט, בלי צילומים).

**הפירוט הממוספר:**

0. **זהות + פרופיל** —
   - **0a · `app-identity`** `[G]` (בריפו) — סורק את הקוד, מחליט איתך את השם (תצוגה + חנות + סאבטייטל),
     מזהה את הפיצ'רים ואת ה-Pro, וכותב את ה-`README.md` של הריפו (מקור-אמת לזהות). רץ **ראשון**.
   - **0b · `app-profile`** `[H]` — קורא את קוד האפליקציה + **את ה-README** ומראיין אותך → כותב את
     `<slug>/profile.md` (מקור האמת לכל קופי). בשלב הזה אין עדיין צילומי מסך.
1. **הבינארי** — `[G]` — הכנת ה-build בריפו האפליקציה:
   `apple-credentials` → `code-signing-provisioning` → `app-store-review-compliance`
   → `localization-i18n` → `app-icon-generator` → (`apple-hig-design-review`, אופציונלי) → build.
2. **דף פרטיות** — `[B]` — `add-app-to-site` **Phase A** (לפני המדיה — **לא צריך מדיה**) מפיק את ה-privacy URL
   (`<your-site>/privacy-policy/<slug>/`). ⚠️ נדרש לפני שליחה לחנות.
3. **מדיה לחנויות** — `[G]` — `appstore-media` לוכד מהאפליקציה הרצה (קורא את הפרופיל
   לסדר-המסכים ולכיתובים) → `apple-app-store-screenshots` להתאמות נקודתיות. הפלט נכתב
   **ל-Hub**: `<slug>/media/apple/`.
4. **קופי לחנויות → Hub** — `[H]` — `store-metadata-writer` קורא profile + media + `DATA.md`, ומפעיל
   את ה-workers (`app-store-metadata` + `aso-keywords` + `play-store-metadata`) שכותבים את המטא-דאטה
   הרב-לשונית **ל-Hub** (`<slug>/store/{apple,play}/metadata/` — ה-SoT), כולל release notes לפי גרסה.
   **לא** כותבים ל-fastlane של הריפו — זה קורה רק בשלב 5.
5. **שליחה** — `[G]` — `ship-apple-app`: מאמת שהכול מוכן → build → **מפעיל את `app-store-deliver`**
   (sync מה-Hub כולל release notes של הגרסה; **מאמת שלמות — אם חסר נתון, חוסם ומפנה ל-`store-metadata-writer`**;
   ASC API: metadata + צילומים + IAP; auth מ-`DATA.md`) → העלאת הבינארי → צעדי אתר App Store Connect
   → submit. (מסלול חלופי: `notarize-and-distribute` ל-DMG ישיר.)
6. **נוכחות באתר** — `[B]` — `add-app-to-site` **Phase B** (אחרי המדיה): כרטיס / דף אפליקציה / אתר-מוצר + לינק לחנות.
   **media-gate:** tier 2/3 צריכים `media/apple/` (מ-3); אם חסר — הרץ `appstore-media` קודם, או רד ל-tier 1.
7. **שיווק + מעקב** — `[H]`/`[G]` — `campaigns/` + `ads/` (ב-Hub) · `app-store-reviews-responder` (גלובלי).

**סדר ותלויות בקצרה:** 0a (זהות/README) ואז 0b (פרופיל) — תמיד ראשונים · 1 ו-2 במקביל אחרי 0 ·
3 צריך build (מ-1) · 4 צריך profile (0) + מדיה (3), וכותב **ל-Hub** · 5 מסנכרן מה-Hub (מ-4),
מאמת (חוסם אם חסר), ודורש שה-2 הושלם · 6 אחרי 5 · 7 שוטף.

## ג. הסבר לכל סקיל

לכל סקיל: **מה עושה · שואב מ · מפעיל · תלוי ב.** ("מפעיל — אין" = לא מריץ סקיל אחר.)

### שלב 0 — זהות + פרופיל

0. **app-identity** `[G]` (בריפו)
   - מה עושה: סורק את הקוד, מציע ומחליט **איתך** את השם (תצוגה במכשיר + App Store + סאבטייטל) תוך בדיקת ASO,
     מזהה את רשימת הפיצ'רים ואת ה-Pro/IAP, מעדכן את שם-התצוגה ב-build/Info.plist, וכותב את ה-`README.md`
     של הריפו (בלוק זהות + רשימת פיצ'רים) — מקור-האמת לזהות. רץ **ראשון, לפני** `app-profile`.
   - שואב מ: קוד האפליקציה + שיח איתך + `aso-keywords` (בדיקת שם/סאבטייטל).
   - מפעיל: נשען על `aso-keywords` (לא מריץ סקיל אחר ישירות).
   - תלוי ב: כלום — **השלב הראשון בריפו.**
1. **app-profile** `[H]`
   - מה עושה: קורא את קוד האפליקציה כאנליסט-מוצר + מראיין אותך, וכותב `profile.md`
     (דוסייה עובדתי + "Derived copy" מוכן לשימוש חוזר). מקים גם את תיקיית `media/apple/`
     (האייקון בלבד כרגע — **לא** לוכד מדיה).
   - שואב מ: קוד האפליקציה (קריאה בלבד) + **ה-`README.md` של `app-identity`** (שמות + דירוג פיצ'רים) + הראיון איתך + `hub/PRODUCT.md` (טון).
   - מפעיל: אין.
   - תלוי ב: `app-identity` (ה-README) — רץ אחריו. (`add-app-to-site` ו-`store-metadata-writer` קוראים לו אם הפרופיל חסר.)

### שלב 1 — הבינארי `[G]` (רץ בריפו האפליקציה)

2. **apple-credentials**
   - מה עושה: הבעלים היחיד של תעודות ו-credentials — יצירה, `.p12`, notary profile, App Store Connect API key.
   - שואב מ: חשבון אפל / ה-Keychain שלך.
   - מפעיל: אין.
   - תלוי ב: כלום. **כל סקילי החתימה/ההעלאה שואבים ממנו.**
3. **code-signing-provisioning**
   - מה עושה: מסביר את מודל החתימה (cert · App ID · entitlements · profile), מאבחן את הפרויקט ומפענח שגיאות.
   - שואב מ: הגדרות ה-build וה-profiles בפרויקט.
   - מפעיל: אין.
   - תלוי ב: `apple-credentials` (לסוגי תעודות ויצירתן).
4. **app-store-review-compliance**
   - מה עושה: סורק מול מדריך הביקורת של אפל, מדרג ממצאים ומתקן בטוחים (usage strings,
     privacy manifest, IAP, מחיקת חשבון, demo-mode לבודק).
   - שואב מ: קוד האפליקציה, ה-entitlements וה-privacy.
   - מפעיל: אין.
   - תלוי ב: כלום. (ה-demo-mode כאן הוא **של הבודק** — שונה מה-demo-mode השיווקי של `appstore-media`.)
5. **localization-i18n**
   - מה עושה: לוקליזציה **בתוך** האפליקציה (`.strings`/`.xcstrings`): מחרוזות קשיחות, שלמות שפות, RTL. (לא טקסט החנות.)
   - שואב מ: קובצי המחרוזות בפרויקט.
   - מפעיל: אין.
   - תלוי ב: כלום.
6. **app-icon-generator**
   - מה עושה: מייצר AppIcon set מלא לכל הפלטפורמות מתמונת 1024 אחת (או מייצר אייקון התחלתי).
   - שואב מ: תמונת מקור.
   - מפעיל: אין.
   - תלוי ב: כלום (עצמאי).
7. **apple-hig-design-review** (אופציונלי)
   - מה עושה: סקירת עיצוב/נגישות מול ה-HIG, המלצות מדורגות לפי impact.
   - שואב מ: ה-UI של האפליקציה.
   - מפעיל: אין.
   - תלוי ב: כלום.

### שלב 2 + 6 — האתר `[B]` (רץ מ-`<site>`)

8. **add-app-to-site**
   - מה עושה: מעלה את האפליקציה ל-<your-site> בשתי פאזות סביב המדיה. **Phase A** (שלב 2, **לפני** המדיה):
     דף פרטיות → privacy URL — **לא צריך מדיה.** **Phase B** (שלב 6, **אחרי** המדיה): כרטיס / דף אפליקציה / אתר-מוצר.
   - שואב מ: הפרופיל ב-Hub + (ב-Phase B) `media/apple/` (קורא ומעתיק — **לא** מזיז את המקור).
   - מפעיל: אין (קורא ל-`app-profile` אם הפרופיל חסר).
   - תלוי ב: `app-profile` (פרופיל קיים). **Phase A — רק פרופיל, בלי מדיה.** **Phase B media-gate:** tier 2/3
     דורשים `media/apple/` (מ-`appstore-media`); חסר → הרץ `appstore-media` קודם, או רד ל-tier 1 (אייקון+משפט, בלי צילומים).

### שלב 3 — מדיה `[G]` (לוכד בריפו, כותב ל-Hub)

9. **appstore-media** (גם **תסריטאי**)
   - מה עושה: קודם כותב `media-script.md` (אסטרטגיה: חוזקות/ייחודיות/מונטיזציה/יעילות + storyboard
     לצילומים ולווידאו) בתיקיית המדיה; ואז לוכד צילומי מסך + סרטון App Preview מ-XCUITest demo flow
     שמממש את ה-storyboard, ממיר ומאמת מול מפרטי אפל, ומפיק כיתובים + תוכנית עריכה (נגזרים מהתסריט).
   - שואב מ: ה-build של האפליקציה (צריך Xcode) + **הפרופיל** (סדר-מסכים, hero, מבדלים, מונטיזציה, טון).https://appstoreconnect.apple.com/login
   - מפעיל: `apple-app-store-screenshots` (להתאמת תמונה בודדת, לפי צורך).
   - תלוי ב: build (שלב 1) + פרופיל (שלב 0). כותב ל-`<slug>/media/apple/` ב-Hub (מכוונים את ה-`-o` לשם).
   - **בעלים של עץ-המדיה הקנוני** (`<App>/<locale>/{screenshots,app-preview,iap,raw}/`, תוצרי-תסריטאי בשורש apple) — מוגדר פעם אחת בראש `appstore-media/SKILL.md`; `store-metadata-writer` / `app-store-metadata` / `app-store-deliver` צורכים נתיבי-עלה ממנו ולא מגדירים מחדש.
10. **apple-app-store-screenshots**
    - מה עושה: מתאים תמונה בודדת קיימת לגודל פיקסלים מדויק (padding/blur/crop). הנתיב הקל כשאין צורך בלכידה מלאה.
    - שואב מ: קובץ תמונה בודד.
    - מפעיל: אין.
    - תלוי ב: כלום (כלי-עזר; בשימוש `appstore-media` ו-`app-store-metadata`).

### שלב 4 — קופי לחנויות `[H]` (נכתב ל-Hub; ה-fastlane מסונכרן רק ב-deliver)

11. **store-metadata-writer** — **הגשר/המתזמר**
    - מה עושה: קורא את הפרופיל ואת `DATA.md`, מרכיב בלוק קופי ניטרלי-לחנות, ממפה לשדות App Store מול Play
      (כולל הבדלי keywords/subtitle), ומעביר את מכניקת הקבצים ל-workers. רץ מ-Hub וכותב את המטא-דאטה
      **ל-Hub** (`<slug>/store/{apple,play}/metadata/` — ה-SoT), כולל release notes לפי גרסה. **לא** מסנכרן ולא מעלה.
    - שואב מ: הפרופיל + `media/apple/` + `DATA.md` (פרטי קשר/copyright/URLs) ב-Hub + `hub/PRODUCT.md` (טון).
    - מפעיל: `app-store-metadata` + `aso-keywords` + `play-store-metadata`.
    - תלוי ב: `app-profile` (פרופיל); ה-privacy URL מ-`add-app-to-site` Phase A. (כשה-sync בשלב 5 מדווח חוסר נתונים — חוזרים לכאן למלא את ה-Hub.)

## ד. כללי הזהב

1. **`app-identity` ואז `app-profile` — ראשונים.** ה-`README.md` (זהות: שם + פיצ'רים + Pro) נכתב בריפו ומזין את הפרופיל; שום קופי לפני שהפרופיל קיים ב-Hub.
2. **אף פעם לא ממציאים.** כל שדה מתחקה לפרופיל או לתשובה מפורשת. חסר? עדכנו את הפרופיל קודם, אז גזרו מחדש.
3. **דף פרטיות לפני שליחה לחנות.** `add-app-to-site` Phase A מפיק את ה-privacy URL שהחנות דורשת — **רץ מוקדם, בלי תלות במדיה.**
4. **המדיה נולדת בשלב 3** (`appstore-media`, בריפו האפליקציה) ונכתבת ל-Hub (מאחסן וצורך, לא לוכד). **Phase B של `add-app-to-site` (נכס באתר, tier 2/3) תלוי בה** — לפני המדיה אפשר רק דף פרטיות (Phase A) או כרטיס tier 1.
5. **כל סביבה והסקילים שלה:** פרופיל/חנויות-קופי/שיווק → מ-**Hub** · אתר → מ-**`<site>`** · בינארי/לכידה/workers → מ-**ריפו האפליקציה**.
6. **טון בשתי שכבות:** `hub/PRODUCT.md` = טון המוצר (מאסטר, ברירת מחדל בכל מקום). ``<site>`/PRODUCT.md` יורש ממנו ודורס רק תצוגת-אתר ספציפית.

   **6א. תקן ואכיפה הם שני קבצים.** ה-`PRODUCT.md` הוא התקן; `copy-edit` (`~/.claude/skills/`, ברמת המשתמש כדי שישרת כל פרויקט) הוא המעבר שמיישם אותו על טקסט קיים, **בכל השפות**. כל סקיל שכותב טקסט ללקוח מריץ אותו לפני המסירה — `app-profile` (6b), `store-metadata-writer` (6b), `add-app-to-site` (B.7b), `translate-site` (Phase 2), `localization-i18n` (4b), `app-identity` (6b), `app-store-reviews-responder` (3). `measure_copy.py` מודד כל locale בכללים שלו (סמני פסוקית לפי שפה, תווים במקום מילים ליפנית וסינית) ומשווה כל תרגום לאנגלית טענה-מול-טענה. **המפה המלאה — איזה חלק יושב באיזה קובץ — בסוף `PRODUCT.md`.**

   **6ב. שער הקופי חוסם שליחה.** `sync_from_hub.sh` של שני סקילי ה-deliver מריץ את הבדיקה על המטא-דאטה המסונכרנת ו**יוצא ≠ 0** אם תרגום חסר, זהה לאנגלית (לא תורגם), או נושא מספר טענות שונה. מתקנים ב-Hub וחוזרים לסנכרן; אם ההבדל מכוון — `--skip-copy-check`. בשפה שאיש כאן לא קורא, ההשוואה הזו היא הבדיקה היחידה שקיימת.
7. **מטא-דאטה: ה-SoT ב-Hub; ההעלאה ע"י סקיל deliver יחיד.** המטא-דאטה הרב-לשונית + צילומים + release notes (לפי גרסה) + IAP חיים ב-`<slug>/store/`. `fastlane/` בריפו נגזר ומסונכרן **רק בזמן השליחה** ע"י **`app-store-deliver` / `play-store-deliver`** (משטחי השליחה היחידים): `sync_from_hub` **מאמת שלמות וחוסם העלאה אם חסר נתון** — אז חוזרים ל-`store-metadata-writer` למלא את ה-Hub. סקילי ה-metadata כותבים/מאמתים בלבד (לא מעלים). בריפו האפליקציה נשאר רק ה-`README.md`.

   **7א. "משוך והשווה" לפני כל דחיפה — שלב חובה.** ה-Hub הוא מקור האמת **רק אם איש לא ערך בקונסולה מאז ה-deliver האחרון** — ובפועל עורכים. לכן, אחרי ה-sync ולפני כל העלאה, מריצים את ה-guard שמושך את הליסטינג **החי** ומשווה אותו ל-Hub:
   - `app-store-deliver/scripts/pull_and_diff.rb <slug> <bundle-id> <version>`
   - `play-store-deliver/scripts/pull_and_diff.sh <slug> <package-name>` (משווה טקסט **וגם כל סט תמונות לפי hash של התוכן** — `supply` משנה שמות בהורדה, אז שמות קבצים לא מוכיחים כלום)

   שלוש התוצאות: `in sync` = ממשיכים · `hub adds` = השדה ריק בחנות, ה-deliver רק מוסיף — בטוח · **`CONFLICT` / `MISSING IN HUB` = עוצרים.** במקרה הזה החנות לרוב **מקדימה** את ה-Hub: מציגים למשתמש כל התנגשות, ו**מבצעים back-port של מה שהוא רוצה לשמור אל תוך ה-Hub** (דרך `store-metadata-writer`) לפני השליחה. לא דורסים עריכות מהאתר רק בגלל ש"ה-Hub הוא ה-SoT".

   **שתי הסכנות שהשלב הזה מונע — ולכל אחת חנות אחת בלבד.** *הופרד 2026-09-09; קודם הן הוצגו יחד, כאילו שתיהן חלות על שתיהן.*

   - **מחיקת מדיה — בשתי החנויות, בשני שמות.** ההעלאה דורסת סטים: `supply` ב‑Play, ו‑`overwrite_screenshots` / `overwrite_preview_videos` ב‑`deliver` של אפל. נכס שקיים בחנות ואינו ב‑Hub **יימחק מהליסטינג החי**. המעקה מדווח עליו — ב‑Play כ‑`MISSING IN HUB`, ובאפל כ‑`ORPHAN`. **שם אחר, אותו מצב, אותה סכנה.**
   - **מטא-דאטה קפואה — אפל בלבד.** אם הגרסה ב‑`WAITING_FOR_REVIEW` / `IN_REVIEW` / `PENDING_APPLE_RELEASE`, העלאה מחייבת לשלוף את ההגשה מהתור ולאבד את מקומה, ולכן דורשת אישור מפורש. **ל‑Play אין מקבילה** — ה‑API שלה אינו חושף שדה סטטוס בדיקה כלל, ולכן אין תור לאבד בו מקום.


   **7ב. לכל משטח יש כותב אחד.** ל-`fastlane/` בריפו האפליקציה יש כותב יחיד: `sync_from_hub.sh`, בזמן שליחה. כל כלי אחר שכותב לשם מחבר תוכן לתוך תיקייה נגזרת, והתוכן הזה **יימחק** בהרצה הבאה — הסנכרון רץ `rsync -a --delete`, כך שכל מה שקיים ב-`fastlane/` ולא קיים ב-Hub נעלם בלי הודעה.
   - **כלי שמחבר טקסט ליסטינג כותב ל-Hub** (`<slug>/store/`), לעולם לא ל-`fastlane/` של הריפו. אם הוא יודע לכתוב רק ל-`fastlane/` — זה מצב ה"פרויקט העצמאי", והוא **סותר** קיום ערך ב-Hub. אפליקציה שיש לה תיקייה ב-Hub מחוברת רק משם.
   - **צילומים ווידאו** נכתבים לעץ המדיה הקנוני `<slug>/media/apple/<App>/<locale>/`. `fastlane/screenshots*/` הוא השטחה שלו לפורמט ש-`deliver` דורש, לא מקום שמאחסנים בו לכידה.
   - **תוכן שנמצא ב-`fastlane/` ואינו ב-Hub הוא לא זבל ולא מקור אמת — הוא עבודה שלא הוחזרה.** מחזירים אותה ל-Hub דרך `store-metadata-writer` (וצילומים דרך `appstore-media`), מריצים עליה `copy-edit`, ורק אז מסנכרנים. מוחקים רק אחרי שיש עותק ב-Hub.
   - **`fastlane/` נכנס ל-`.gitignore` רק כשהתנאי הזה מתקיים** — כשכל מה שבתוכו ניתן לשחזור מה-Hub. עד אז ההתעלמות ממנו מוציאה מבקרת הגרסאות את העותק היחיד.
   - **הכלל חל גם בכיוון ההפוך:** לפני שהסנכרון דורס את `fastlane/`, אם יש שם שדה שאין ב-Hub — עוצרים, כמו ב-`CONFLICT` של 7א. "ה-Hub הוא ה-SoT" הוא לא היתר למחוק טקסט שנכתב במקום אחר. **השער אוכף את זה**: הסנכרון משווה את מה שכבר יושב בריפו מול ה-Hub, **חוסם** על קובץ שה-Hub לא יכול לשחזר (`--discard-repo-extras` דורס), ומזהיר על שדה שקיים בשניהם ושונה. release notes נבדקים מול **הגרסה שנשלחת**, כי הערות של גרסה קודמת לא הופכות את אלה של הגרסה הזו לניתנות לשחזור.
   - **release notes לפי פלטפורמה:** אפליקציה אוניברסלית יכולה לדרוש נוסח שונה ל-Mac ול-iPhone. הארכיון תומך ב-`release-notes/<ver>/<locale>.<platform>.txt` לצד `<locale>.txt` — אותה קונבנציה כמו `<field>.<platform>.txt` במטא-דאטה. בלי `--platform` נשלח הנוסח המשותף.

   ובאותה רוח — **אל תניחו שהחנות ריקה.** ליסטינג יכול להיות חי ב-`internal`/`alpha` בזמן שה-Hub עדיין חושב ש-Play לא התחיל (`google_play_track_version_codes`), וגרסה יכולה להיות מוגשת ולא ב-PREPARE_FOR_SUBMISSION. בודקים מול ה-API, לא מול הזיכרון.
8. **`DATA.md` (שורש ה-Hub) = דאטה כלל-סטודיו:** פרטי קשר (review info), copyright, URLs ברירת-מחדל, נתיב ה-`.p8` (+ Issuer/Key ID), ו-**`conversational language`** (השפה שבה כל הסקילים משוחחים עם המשתמש). שואבים משם, לא ממציאים ולא שואלים.
   **המפתחות עצמם אינם כאן ולעולם לא בריפו כלשהו** — כולם תחת `$DEV_ROOT/myData`, שאינה תיקיית git. `DATA.md` מחזיק רק **מזהים ונתיבים** (issuer id, key id, נתיב ה-`.p8`); הסוד עצמו נקרא מ-`myData` בזמן השימוש. מפת התיקייה המלאה נמצאת בראש `DATA.md`.

> **IAP/Pro — מכוסה ב-`app-store-deliver`:** מטא-דאטה של מוצרי IAP (Display Name פר-locale + Description + מחיר + **צילום לבודק**) מועלית דרך ה-**ASC API הרשמי** (`Spaceship::ConnectAPI`, token/p8), נכתבת ל-Hub תחת `<slug>/store/apple/iap/<product-id>/` ע"י **`app-store-metadata`** (בתזמור `store-metadata-writer`), וה-`app-store-deliver` רק מסנכרן ומעלה. פירוט: `plugins/apple-track/skills/app-store-deliver/references/iap-and-asc-api.md`. **Google Play:** מוצרים מנוהלים / מנויים נכתבים ל-Hub ע"י `play-store-metadata` ומועלים ע"י `play-store-deliver` דרך ה-**Play Developer API** (AndroidPublisher v3) — פירוט: `plugins/android-track/skills/play-store-deliver/references/play-iap.md`.
